## 1. 结论摘要

**选路线 A（FFT 谱合成 / 高斯随机场），不选 Perlin / Simplex。Perlin 仅在"退化开关"的意义上保留。**

理由（全部量化，见 §3）：

1. **Perlin 达不到 `DQ-06` 的安全性**。`cell = 30 mm`（约 3.6 × die pitch）时 Perlin 的 Moran's I 只有 **0.563 ± 0.018**（rook 权重），是路线 A（**0.953 ± 0.016**）的 59%；而且 **Perlin 的 I 对频率参数不是单调的，存在盲区**：当 `cell` 落在 die pitch 附近时 I **变成负数**（`cell = 8.4 mm` 时 I = **−0.104**，`cell = 12 mm` 时 I = −0.015）。也就是说，一个把 Perlin 的 `cell` 调"太细"的配置会让相邻 die 反相关——不是"质量略降"，而是**符号错误**，且 YMS 侧完全可能把它当成"负的空间相关"检出。Perlin 要过 0.3 需要 `cell ≥ 2.4 × die pitch`（本实测：20 mm / 8.4 mm = 2.38 → I = 0.304）。
2. **路线 A 的 I 是可解析预测的**，因此可以写进校验规则而不是靠调参命中：实测验证了恒等式
   **`Moran's I(rook4) ≈ C(die pitch) / C(0)`**（§3.2 表，路线 A 的实测 I 与 `exp(−p²/2ℓ²)` 在 ℓ ≥ 0.8p 时吻合到 ±0.02）。由此得到生成器的设计规则：**ℓ ≥ 0.64 × die pitch** 才能过 0.3；若要留 1.5× 的**数值余量**（I ≈ 0.46），则 **ℓ ≥ 0.8 × die pitch**（建议 `design.MD` 的默认值取 ℓ ≈ 1~3 × die pitch）。这条规则与晶圆尺寸、die 数量无关（已在 pitch = 4 / 5 / 8.4 / 12 mm 四种采样密度上验证）。
3. **性能不是选型因素**：300 mm / 997 die 下单 wafer 单物理量完整建场+求值，**A1（FFT, 256²）2.33 ms**，Perlin（4 octaves）3.65 ms——**FFT 反而更快**。折算 25 wafer × 12 物理量 = 单 Lot 0.70 s（A1）vs 1.09 s（Perlin），相对 `SD-SCL-020` 的 30 s 预算分别占 2.3% / 3.6%（§3.5）。
4. **实现复杂度差距远小于"失败应对"预期**：FFT 谱合成本体 **97 行**，Perlin **69 行**（均为去注释/空行后的实现行数）。唯一的"贵"是 Hermitian 对称的系数装配（约 30 行）与必须手写的行/列二维 FFT（约 15 行，原因见 §3.6）。
5. **`MathNet.Numerics` 的依赖树是干净的**：`5.0.0` 对 `net6.0` / `netstandard2.0` **零包依赖**，无原生资产，MIT，单程序集 1.5 MB；`net10.0` 下解析到 `lib/net6.0/MathNet.Numerics.dll`。不违反 `SD-SYS-180/181`（该条只禁止 Core 引 Avalonia*/System.CommandLine/Spectre.Console）。**但**：它的 FFT **默认会探测原生 MKL provider**（探测成功会静默换实现 ⇒ 破坏跨 RID 字节一致），必须显式钉住；且它**根本没有可用的二维 FFT**（§3.6）。
6. 因此：**`Core/Physics/` 按路线 A 写，并把 `MathNet.Numerics` 作为唯一新增的第三方数值依赖引入 Core**（设计册 §1.5 已经这么预算了）。同时**必须在写生成引擎之前**按本笔记 §4 修正 `DQ-06` 的检查口径——否则会出现"达到门槛但没测到该测的东西"的假通过（§3.3：关掉平滑场后 I 仍有 0.486）。

### 2.1 晶圆与 die 图（实验假设）

| 项 | 取值 | 说明 |
| --- | --- | --- |
| 晶圆 | 300 mm，R = 150 mm | 与 `SD-SCL-020` 的 25k die / 25 wafer 一致 |
| die 间距 | **8.4 mm** 方格 | 圆内中心命中 ⇒ **997 die/wafer**（≈ 1000，符合票面口径） |
| die 坐标 | die **中心**，圆心为 (0,0) | 边缘不完整 die 不参与（口径可配，见 §5 未验证项） |

> 结论中的**相对量**（I ≈ C(p)/C(0)、ℓ ≥ 0.64p）与绝对尺寸无关，只依赖 `die pitch`；绝对耗时随 die 数线性（见 §3.5）。

### 2.2 Moran's I 的定义（票面/文档未定义，本笔记代为定义并实测敏感性）

文档只写了 `DQ-06`：「相邻 die 参数差 vs 随机 die 参数差」「Moran's I > 0.3」，**没有给出权重矩阵**（全仓 grep 确认：`doc/` 下无任何 `w_ij` / 邻接 / 权重定义）。本笔记采用标准 Moran's I：

```
I = (n / S0) · [ Σ_i Σ_j w_ij (x_i − x̄)(x_j − x̄) ] / [ Σ_i (x_i − x̄)² ] ，  S0 = Σ_i Σ_j w_ij
```

并实测了 4 种权重定义的敏感性（§3.1 表，n = 997）：

| 权重 | 定义 | 备注 |
| --- | --- | --- |
| **rook4（本笔记的主口径）** | 方格上边相邻（|Δix|+|Δiy| = 1） | 最贴合 `DQ-06`「相邻 die」的字面意思；且满足恒等式 `I ≈ C(pitch)/C(0)`，可解析预测 |
| queen8 | 8 邻域（含对角） | 对角滞后为 p·√2，对 Perlin 这种 ACF 衰减快的场会显著压低 I（0.563 → 0.451） |
| queen8 行标准化 | 同上 + 行标准化 | 与 queen8 几乎相同 |
| knn4 反距离 | 最近 4 die，w = 1/d | 与 rook4 几乎相同 |

结论：**权重定义对路线 A 的判定不敏感**（0.932 ~ 0.954），**对 Perlin 敏感**（0.450 ~ 0.569，安全边际从 +0.26 掉到 +0.15）。建议 `DQ-06` 检查器**同时算 rook4 与 queen8，两者都必须过**（实现成本几乎为零）。

### 2.3 目标协方差（路线 A 的"目标"是什么）

各向同性高斯：`C(r) = exp(−r² / 2ℓ²)`，对应功率谱（循环/mm）`S(k) = 2πℓ² · exp(−2π²ℓ²|k|²)`。
选择它的理由：单一参数、与 die pitch 有闭式关系（§3.2）、在合成网格上可用 circulant embedding 精确实现。
（其他协方差——Matérn / 指数 / 球状——本笔记**未实测**，见 §5。）

### 2.4 环境

macOS / osx-arm64 / .NET SDK 10.0.402 / `MathNet.Numerics` 5.0.0（包源 nuget.azure.cn）/ `Release` 构建。

### 3.4 批间 / wafer 间相关性

做法（两条路线同一构造）：lot 级共享场 `L_lot`，每 wafer 再抽一个独立场 `L_w`，取

```
L_wafer = √ρ · L_lot + √(1−ρ) · L_w        （两者均为单位方差、相互独立）
```

8 个 wafer 的同 lot 内成对 die 级 Pearson 相关（997 die/wafer）：

| ρ（目标） | A1 实测（同 lot） | Perlin4 实测（同 lot） | A1 跨 lot 对照 |
| --- | --- | --- | --- |
| 0.00 | −0.028 | 0.042 | −0.049 |
| 0.25 | 0.204 | 0.321 | −0.046 |
| 0.50 | 0.469 | 0.550 | −0.050 |
| 0.75 | 0.738 | 0.773 | −0.056 |
| 0.90 | 0.897 | 0.908 | −0.061 |
| 1.00 | 1.000 | 1.000 | −0.068 |

⇒ **两条路线都能表达 wafer 间相关性，且构造与路线无关**（就是两个独立场的线性混合，两个场各自的性质不参与）。跨 lot 对照 ≈ −0.05（在 30 mm 相关长度、997 die 下相关估计的噪声约 ±0.05~0.09，双 wafer 单点估计；25 wafer 平均后会收敛到 ±0.02）。
⇒ **这不是"路线选择"的判据，而是"种子派生 + 混合权重"的设计点**：`ρ` 必须进配置，且 `L_lot` 的种子必须只依赖 `seed_root + lot_id`（`SD-GEN-194`：不得依赖 workbookId）。
⇒ 另一条"振幅相关性"路径（`SD-GEN-075` 的"振幅按片抽取"）是纯标量抽取（`γ_w ~ N(γ_lot, σ_γ)`），同样与路线无关。

| A3 高斯卷积 n=256 | 13.5 ms | 13.8 ms | 4.15 s |
| **B Perlin oct=4** | 3.30 ~ 3.44 ms | 3.59 ~ 3.65 ms | 1.08 ~ 1.09 s |

**纯求值部分（场建好后只算 997 个 die）**：A1 = **4.3 µs**；Perlin(4oct) = **31 µs**。

**对照 `SD-SCL-020`（单 Lot ≤ 30 s，含入库与聚合）**：A1 n=256 占 **2.3%**；即使按最差的 n=512 也只占 9%。**两条路线的性能都远不构成瓶颈**，性能不能作为选型依据。
（注：上表 median 里 max 列的抖动来自 GC——每次建场要分配 0.5~4 MB 的 `Complex[]`；实现时应复用缓冲区。A3/A2 的耗时大头是"晶圆盘探针归一化"，不是本体。）

### 3.6 `MathNet.Numerics`：TFM、依赖树、正确性风险（票面问题 4）

**版本与依赖（主源：nuget.azure.cn 的 registration API + 下载包的 `.nuspec`）**

| 项 | 实测 |
| --- | --- |
| 最新稳定版 | **5.0.0**，发布 **2022-04-03**（至今 3.5 年无稳定版更新） |
| 预发布 | 6.0.0-beta1（2023-12-17）、**6.0.0-beta2（2025-03-02，新增 net8.0 TFM）** |
| TFM | net461 / net48 / net5.0 / **net6.0** / netstandard2.0 |
| net10.0 下解析结果 | `lib/net6.0/MathNet.Numerics.dll`（`project.assets.json` 实测） |
| **包依赖** | **net5.0 / net6.0 / netstandard2.0 组均为空**（只有 net461 需要 System.ValueTuple） |
| 原生资产 | 主包**无**（MKL/CUDA/OpenBLAS 适配器已拆成独立包） |
| 许可 / 体量 | MIT / 单程序集 1.5 MB |
| `dotnet list package --include-transitive` | 只有 `MathNet.Numerics 5.0.0` 自身，**零传递依赖** |

⇒ **不会"污染" Core 的依赖树**；`SD-SYS-180/181` 只禁止 Core→Avalonia*/System.CommandLine/Spectre.Console，MIT 数值库在 `design.MD` §1.5 已列为选用（"空间场谱合成：自研（基于 MathNet.Numerics 的 FFT）"）。
**风险**：稳定版停滞（3.5 年），维护节奏慢（GitHub 仓库未归档，最新 push 2025-03-03，335 个 open issue）。若在意，可只取 6.0.0-beta2 的 net8.0 资产，或**完全不引 MathNet**（见下）。

**⚠ 三条必须写进实现的坑（主源：ilspycmd 反编译 5.0.0 的 `MathNet.Numerics.dll`）**

1. **托管 provider 没有二维 FFT。** `Fourier.Forward2D/Inverse2D/ForwardMultiDim` 全部走 `provider.ForwardMultidim`，而 `ManagedFourierTransformProvider.ForwardMultidim` 的实现体就是 `throw new NotSupportedException();`（实测运行时确实抛异常）。**必须自己写"逐行 1D → 逐列 1D"**（本实验约 15 行）。二维重载只有在加载了原生 MKL provider 时才可用。
2. **默认会探测原生 provider。** `FourierTransformControl.UseDefault()` → `UseBest()` → 探测程序集 `MathNet.Numerics.Providers.MKL, ...(MklFourierTransformControl)`。一旦某个依赖/手工放置的 DLL 让它探测成功，FFT 会**静默换成 MKL 实现**（不同的舍入 + MKL 自身的 CPU 分派），`SD-GEN-197c` / `DQ-21` 的字节级一致就没了。**对策：启动时显式钉住**——`FourierTransformControl.UseManaged()`，或设 AppContext 开关 `Switch.MathNet.Numerics.Providers.DisableNativeProviders = true`（2 行代码，成本极低，不要省）。
3. **twiddle 因子用 `Math.Cos` / `Math.Sin` 逐 butterfly 现算**（`Radix2Step`）。.NET 的三角/对数函数是平台 libm 实现，**跨 RID 不保证逐位一致**。影响量级：1 ULP 级（相对 1e-16），在 `precision` 舍入（mV→3 位等）之后不可见——但**理论上存在"恰好落在舍入边界"的极小概率翻转**，属于 `SD-EXT-106` 要覆盖的范围，本笔记**未验证**。同样的隐患存在于 Box–Muller（`Math.Log`）等所有高斯抽样路径——这是全项目的问题，不是本路线新增的（见 §5）。

**确定性实测（osx-arm64，`DOTNET_PROCESSOR_COUNT` = 1 / 2 / 10 三次运行）**：字段位模式 FNV-1a 校验和 **完全一致**（含长度 4096、走并行分支的 1D FFT）。主源佐证：`Radix2ForwardParallel` 与 `Radix2Forward` 的每个 butterfly（`Radix2Step`）在两种路径下逐元素相同，多线程只是把**互不相交**的 butterfly 分块并行，不改求和顺序 ⇒ **线程数不影响位模式**。
⇒ 但**跨 RID 的 `Math.Sin/Cos` 差异**仍然存在（无法在本机验证，见 §5）。

**替代路线（不引任何第三方库）**：A2（正弦和 / 谱表示法）在数学上就是"给定谱 → 反变换求场"，但**根本不需要 FFT**，48 行。本实验里它的 Moran's I（0.953）、能力与 A1 完全等价。代价：**逐点求值是 O(K) 三角函数**（192 模态 = 1.6 ms / wafer），且要做归一化探针（15 ms）⇒ 单 Lot 4.87 s（仍只占预算 16%）。如果 `Core` 引入第三方库在评审上有阻力，A2 是**零依赖的可行替代**，但需要在"缺陷注入需要在任意 (x,y) 求值"的场景下评估调用频率。

### 3.7 实现复杂度（票面问题 4 的第二半）

| 路线 | 本体行数（去注释/空行） | 文件 | 主要正确性风险 |
| --- | --- | --- | --- |
| A1 FFT 谱合成（MathNet） | **97** | `RouteA_FftSpectral.cs` | Hermitian 对称装配（自共轭模态的方差要少乘 2）、DFT 缩放约定（1/N²）、二维要在行/列手动分解、provider 钉住 |
| A2 正弦和（无 FFT） | **48** | `RouteA2_SinusoidSum.cs` | 模态幅度 = √(2·S(k)·dA) 的离散化、频率截断半径、逐点三角函数成本 |
| A3 高斯卷积（无 FFT） | **60** | `RouteA3_GaussianConvolution.cs` | 核截断半径（4σ）、周期回绕、两次一维卷积的边界 |
| B Perlin fBm | **69** | `RouteB_Perlin.cs` | 梯度置换表、晶格与 die 网格对齐（本实验每 wafer 随机平移晶格）、octave 下限、归一化探针 |
| （公共）die 图 + Moran's I 评分器 | 约 120 | `WaferMap.cs` | 权重矩阵定义、边界 die 的度不齐 |

⇒ **复杂度不是选型判据**：A1 比 Perlin 多 28 行（+41%），而 A1 多出来的部分是一次性写对的（装配对称性 + 手动 2D FFT），Perlin 的复杂度反而是"调参才能对"的隐式复杂度（cell、octaves、对齐三个旋钮互相耦合，且存在负相关盲区）。
⇒ 本实验里 A1 的第一版有一个真实 bug（把铺平的二维数组喂给了 1D IFFT），表现为"场的方差只剩 0.56 倍"——**这是该路线最典型的错误**，建议实现时用 §3.0 的"集成 ACF vs 理论 C(r)"作为单元测试（本实验 40 seeds 集成即可看出偏差）。

## 4. 对切片的影响

### 4.1 `Core/Physics/` 按路线 A 写

- 平滑随机场 `L(x,y)` 的**语义 = 指定协方差的高斯随机场**，实现 = FFT 谱合成（circulant embedding），目标协方差默认 `C(r) = exp(−r²/2ℓ²)`（可扩成 Matérn，见 §5）。
- 生成流程（每个 wafer × 每个物理量）：
  1. 由 `wafer_seed + quantity_id` 派生 RNG → 装配 Hermitian 对称的复谱（幅度由 `S(k)` 给定，相位由 RNG 给）；
  2. 逐行 1D IFFT → 逐列 1D IFFT（**不要用 `Fourier.Inverse2D`**），取实部 × 1/N²；
  3. **在晶圆盘/die 集上归一化到单位方差**，再乘本 wafer 抽到的振幅 `γ_w`；
  4. die 求值 = 双线性插值（die 数 ~1000，4.3 µs）。
- 参数与硬约束（写进配置校验）：
  - `l_corr_mm ≥ 0.8 × die_pitch_mm`（过 `DQ-06` 的必要条件，§3.2）；
  - `h = box/n ≤ ℓ/2`（解析尺度）；`box ≥ 2R + 4ℓ`（避免周期回绕）；
  - `eps/gamma ≤ 1.4`（ℓ=30 mm 时；更一般地 `(ε/γ)² ≤ I_L/0.3 − 1`，§3.3）；
  - `γ`/`α`/`β` **按 wafer 抽**（`SD-GEN-071`），且 `L_wafer = √ρ·L_lot + √(1−ρ)·L_w`。
- 缺陷注入若需要在任意 (x,y) 求值：A1 走双线性插值即可（网格已覆盖整个晶圆），无需为每个缺陷重建场。

### 4.2 要不要引 `MathNet.Numerics`

**推荐引**（`Core` 直接 `PackageReference MathNet.Numerics 5.0.0`），前提是：
- 显式 `FourierTransformControl.UseManaged()`（或 AppContext 开关），把 provider 钉死在托管实现；
- 加一条架构/单元测试，断言 `FourierTransformControl.Provider.ToString() == "Managed"`；
- 只使用它的 FFT（1D）与后续可能需要的分布/统计；不要用它的多维 FFT（不可用）。
理由：零传递依赖、MIT、无原生资产、`design.MD` §1.5 已列；而自己写 radix-2 虽然只有约 50 行，但会引入一个需要自己维护和验证的数值内核。
**若评审拒绝第三方库**：改用 A2（正弦和），零依赖，能力等价，单 Lot 4.87 s。

### 4.3 "失败应对（退化为 Perlin）"要不要预留接缝

**要留，但把接缝定义成"场生成器接口 + `method` 配置键"就够**（`design.MD` 附录 A 的配置示例里已经有 `smooth_random_field: { method: fft_spectral }`）：

```
ISmoothFieldSource { double Sample(double xMm, double yMm); }   // 或按 die 批量返回
  ├─ FftSpectralField   （默认，method = fft_spectral）
  ├─ SinusoidSumField   （零依赖备选，method = spectral_sum）
  └─ PerlinField        （退化，method = perlin）
```
Perlin 实现只有 69 行，**建议一并实现并纳入测试**（成本低），但要带**参数守卫**：`cell ≥ 2.4 × die_pitch`，否则配置校验直接报错——因为本实测显示 `cell ≈ die pitch` 时 I 为**负**（相邻 die 反相关），那不是"质量略降"，而是**误导 YMS 的错误数据**。同时 Perlin 的最细 octave 波长必须 ≥ 2 × die pitch。

### 4.4 必须在写生成引擎之前修正的检查口径（`DQ-06`）

1. **`DQ-06` 必须测"残差场"，不能测复合值**。现状（径向 0.927 / 扇区 0.990 / 关掉平滑场后仍有 0.486）意味着检查会**假通过**。建议：`DQ-06` 在**每个物理量上先扣掉各 wafer 的确定性成分（径向、扇区、均值）再做 Moran's I**；或者在 `disable_smooth_field: true` 时必须 **FAIL 并给出"未检出空间相关"的提示**（现在的实现会 PASS）。这条同时是 `SD-GEN-076`（对照组）能起作用的前提。
2. **权重矩阵必须写进文档**（目前 `doc/` 里没有定义）。建议主口径 **rook4（四个边相邻 die）**，辅助口径 queen8，两者都要过；`(n/S0)` 归一化天然处理晶圆边界的度不齐。
3. **`DQ-06` 的验收应带样本量与余量**：n=997 时零假设 sd = 0.024，门限 0.3 是 12.5σ——**如果现场用更小的 die 数（如 WAT 只有几十个点），这个门限的统计意义完全不同**，需要按 n 重新表述（例如"门限 0.3 且 p < 1e-3"）。本笔记**未对 n < 400 的情形做实测**（见 §5）。

### 4.5 顺带发现的两处文档缺陷（建议单独登记，本笔记不改文档）

1. **`DQ-01` 与 `DQ-06` 的编号混淆**：票面/jira 描述里把「Moran's I > 0.3」挂在 `DQ-01` 下，但 `requirements-spec.MD` §9 中 `DQ-01` = 分布形态、`DQ-06` = 空间自相关；`design.MD` §7.1 `SD-GEN-073` 与 `AC-14` 都写的是 `DQ-06`。**以 `DQ-06` 为准**。
2. **`DQ-06` 的检查项描述「相邻 die 参数差 vs 随机 die 参数差」实际是 Geary's C 的表述**，而判定标准用的是 Moran's I。二者在阈值上不可互换（Geary's C ≈ 1 − I 的量级关系仅在特定权重下近似成立）。建议把描述改成与公式一致。

## 5. 未验证 / 不确定项（不要当成结论用）

1. **跨 RID 逐位一致（`SD-EXT-106`）未验证**：本机只有 osx-arm64。已知 `MathNet` 的 FFT twiddle 与 Box–Muller 都依赖平台 libm（`Math.Sin/Cos/Log`），理论上存在 ULP 级差异；`precision` 舍入后应不可见，但"恰好落在舍入边界"的翻转概率**未评估**。这是全项目级的抽样问题，不属于路线选择的差异。
2. **协方差族只实测了高斯（平方指数）**：Matérn / 指数 / 球状 / 各向异性谱**未测**。如果后续需要"更粗糙"的场（真实晶圆的工艺起伏常呈长尾谱），`ℓ ↔ I` 的闭式关系会变（`I = C(p)/C(0)` 仍然成立，但 `C` 换了）。
3. **die 图口径**：本实验用"die 中心在圆内"（997 die）；实际实现若包含边缘不完整 die 或按 reticle 排布，die 数与邻接关系会变，`I = C(p)/C(0)` 仍成立（对规则方格），但边界 die 的比例会影响 `E[I]` 的零假设方差——**未测**。
4. **未测小样本场景**：WAT 点位只有几十个时的 Moran's I 行为（n=40 时 1/√n ≈ 0.16，0.3 的门限只有 ~2σ）。
5. **未测 `ℓ` 与晶圆尺寸的交互**：ℓ 接近晶圆直径（如 ℓ ≥ 75 mm）时，场在整片晶圆上只有 1~2 个"斑块"，`DQ-03`（sigma 偏差）与 `DQ-05`（wafer 间良率分布）的行为**未测**；本实验最大只测到 ℓ = 60 mm（I = 0.98，仍与理论一致）。
6. **未做并行/分片验证**：25 wafer × 12 物理量在 `SD-GEN-192/193` 的并行分片下必须与串行逐位一致；本实验只验证了单线程与 FFT 线程数无关性（§3.6），**没有**跑多 wafer 并行的位一致性用例。
7. **A2（正弦和）与 A3（高斯卷积）只做了同等条件下的对比**，没有做完整的参数扫描；它们的结论（能过门限、性能可接受）是可靠的，但最优参数**未调优**。
8. **Perlin 的"负相关盲区"只在 die pitch = 8.4 mm 上实测了 cell ∈ {2..60} mm 的网格**；换采样密度时的确切边界（2.4×）**未逐一验证**。
